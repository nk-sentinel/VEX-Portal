# Screens — Phase 6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** The nine screens from `docs/design/ui-spec.md`, in Angular, against the live API.

**Architecture:** Angular standalone components. The design system is DAST-Portal's, already lifted into the Claude Design mockups at `docs/design/ui-mockups.html` — that file is the visual authority, `ui-spec.md` is the behavioural one. Screens 5 and 6 are ONE component differently scoped; the evidence drawer is a side panel, not a modal.

**Spec:** `docs/design/ui-spec.md` (screens, states, constraints the UI must enforce), `docs/design/ui-mockups.html` (visual system, tokens, layout).

## Global Constraints

- Angular 21, matching DAST-Portal. TypeScript strict.
- **Never the word "waiver"** in any label, button, tooltip, table header, notification, or export. The interface says *determination*, *assessment*, *Not Affected*. This is the layer audit and management actually see, and the whole vocabulary exists for them.
- **The UI is never the enforcement point.** Hiding a button is a courtesy to the user; the server enforces. Never assume a hidden control cannot be invoked.
- **Escalation signals never render as supporting a clear.** The API returns them in their own object — keep them there. No red-EPSS token exists in the design system, deliberately, so no future edit can accidentally place a severity colour beside a Not Affected verdict.
- **Risk Acceptance Required is not styled as a determination.** Dashed violet outline, outbound arrow on its actions, dashed row edge. It borrows nothing from the green of a cleared finding, because it is a hand-off and the IQ violation is still open.
- Every screen implements all four states: default, loading, empty, error. An empty queue says "nothing needs review" — good news, said plainly, not an error-shaped void.
- No new npm dependencies beyond what `ng new` and the API client need. Every added package is a future patch obligation.

### Task 1: Scaffold, design system, API client

**Files:** `web/` (Angular workspace), `web/src/app/core/design/` (tokens lifted from the mockups), `web/src/app/core/api/`

- [ ] Angular workspace with strict TypeScript. Lift the token blocks from `docs/design/ui-mockups.html` — the Signal palette, IBM Plex, the outcome ramp, the evidence-tier ramp, the deliberately colourless escalation block, the assessment-state ramp, the expiry bands. A typed API client generated from or hand-written against the live OpenAPI at `/openapi.json`.
- [ ] Tests: the client round-trips against the running API; token values match the mockups exactly.

**Lift the tokens, do not re-derive them.** The mockups encode decisions — `--handoff` sitting outside the verdict hues, no red-EPSS token existing at all — that are easy to lose when re-typing.

### Task 3: Review queue and evidence drawer — screens 5, 6 and the drawer

**Files:** `web/src/app/features/review/`

**This is the screen the team lives in. Build it first among the functional screens and build it properly.**

Finding-level rows by default with a toggle to group by assessment; sortable columns; filters that persist across drawer open/close and navigation; the evidence drawer as a right-hand panel; full keyboard operation (`j`/`k`, `Enter`, `a`/`d`/`s`, `Esc`, `/`).

- [ ] Tests: filters survive a drawer round trip; keyboard navigation moves selection and the drawer follows; the drawer traps focus and returns it to the originating row on close; escalation signals render in their own block with the "not a basis for clearing" line; a Tier 2 clear shows that a second confirmation is required; where the adjudicator abstained, the missing-evidence list renders and is visually distinct from a failed collector.

**Failed collector and abstention must look nothing alike.** One is an outage, the other a limit of the evidence. Rendering them the same way teaches reviewers to treat a broken pipeline as a considered judgement.
